## 实现边界

- 复用现有业务服务、人数解析、乐观并发条件、礼金幂等键、生命周期预览与审计记录；没有改动签到人数、礼金金额及权限规则。
- 工作人员读取现有受限详情；实时事件仅包含空对象变更通知，不携带宾客姓名、礼金、私人备注或回执留言。数据仍经原权限接口读取。
- 现场详情通过宾客 ID 读取当前服务端状态，避免更正/撤销后受列表筛选、分页、同名记录影响而显示旧状态。
- 实时广播适用于项目目前的单个 Node 服务进程。若以后部署多个独立服务实例，需要引入共享广播通道。实际部署的反向代理需允许流式响应；接口已发送禁用代理缓冲的响应头。
- 本轮没有新增数据库迁移，也没有部署操作。

## 第二轮反馈：现场流程精简

本轮按用户补充的 10 项反馈继续调整：

1. 普通列表将数量与操作分为左右两组，刷新稳定靠右；现场名单刷新移至页签栏右侧，队列刷新移至队列标题右侧，减少筛选行和主工具栏拥挤。
2. 手机号可留空，填写时使用共享的 `^1[3-9]\d{9}$` 格式规则。表单、管理员新增/修改接口及 Excel 导入使用一致规则；格式校验不代表号码真实有效。
3. 后台业务输入、表单及宾客端姓名表单设置 autocomplete="off"。这是页面向浏览器发出的关闭自动完成提示，不能保证覆盖浏览器自身设置或密码管理器策略。
4. 现场表单去除编号步骤标题；不需要身份选择的来宾省去身份核对区块，直接填写实到人数。手工登记保留姓名输入，查询失败和同名选择仍明确展示。
5. 代登记成功后清空姓名与本次提交标识，直接开始下一位；同名下一位获得独立标识并入队。失败时继续保留原姓名和标识，避免重试重复写入；连续成功反馈使用同一条 toast，减少堆叠。
6. 同名候选全部已签到、尚无明确选择时默认选中“新增另一位同名宾客”。不会自动覆盖工作人员已经作出的身份选择。
7. 现场空态改为 Ant Design Table 自身的空数据单元格，保留内部居中、固定表头与分页；加载、空数据、连接失败分别展示，取消外部绝对定位覆盖层。
8. 快捷原因 Tag 使用圆角、灰色未选中底色；选中、禁用与键盘交互继续采用原生状态。
9. 通过自助签到或手动现场流程新建的临时档案默认归入“临时到场”；保留原档案 ID、明确同名选择及独立建档规则。
10. 宾客管理“已出席”使用绿色成功状态，“已回执”使用蓝色信息状态，以文字、图标及颜色共同区分。

## 仪表盘开发资源加载故障

复现于 localhost:5173：DashboardPage 模块本身返回 200，实际失败的是图表预构建依赖（echarts 与 echarts-for-react），返回 504。主开发服务与此前的 5189 临时验证服务共用开发缓存，缓存失效后主服务仍引用旧的依赖版本。

修复：Vite 缓存按 mode 分开；图表依赖在启动时明确预构建。停止原临时服务，后续独立验证服务使用 `pnpm dev:web --mode verification --host 127.0.0.1 --port 5189 --strictPort`，不与默认 development 缓存共用。构建环境也使用独立目录。

根路由增加静态加载的中文错误恢复页，页面模块加载失败时提供“重新加载页面”和后台替代入口，不自动刷新丢失上下文，也不显示原始开发者堆栈。该恢复页不依赖失败的业务页面模块。

验证：实际 5173 仪表盘及图表恢复，主开发与 verification 服务交替加载均无失败请求；模拟阻断 DashboardPage 模块时显示中文恢复页，点击重新加载后恢复仪表盘。页面验证拦截业务接口，没有写入真实业务数据。
