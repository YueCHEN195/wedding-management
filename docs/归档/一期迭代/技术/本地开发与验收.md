## 独立验收数据库

建议使用独立验收数据库，避免示例宾客和测试礼金混入正式数据。先停止现有开发服务，再在项目根目录执行（Node 24）：

```bash
pnpm exec cross-env DB_PATH=./data/acceptance.db pnpm db:migrate
pnpm exec cross-env DB_PATH=./data/acceptance.db pnpm db:seed
pnpm exec cross-env DB_PATH=./data/acceptance.db pnpm dev
```

上述命令不会修改原来的 wedding.db。验收完成后停止服务，再正常 `pnpm dev` 就会按 .env 恢复使用原数据库；无需把 .env 改为验收数据库。

种子数据提供 `admin / admin123` 管理员账号。验收库用于测试，不要填写真实礼金或把它当作正式账本。再次使用同一验收库会保留此前的测试数据，建议每项使用不同的测试姓名。

## 打开页面

默认前端地址为 `http://localhost:5173`，后台入口 `/admin`、自助签到 `/checkin`、通用请柬 `/invite`。专属请柬由管理员在“宾客管理”预览或复制。

已有迁移随后端启动执行；仅验收已有功能无需执行 `db:generate`。修改环境配置后需重启开发服务。

## 自动验证记录的口径

问题文档中的测试数量与浏览器结果记录该项完成时的验证，不代表后续版本的最新测试总数。截图是当时的验收证据；重新验收请使用对应问题的操作表。

开发检查可在项目根目录运行：

```bash
pnpm test
pnpm typecheck
pnpm build
```

自动测试使用临时数据库；具体实现以测试代码为准。文档归档本身不需要重复运行应用测试。
