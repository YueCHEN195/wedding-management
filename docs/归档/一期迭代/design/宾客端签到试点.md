## 实现范围与复用边界

- `web/src/guest/guest-tokens.css`：颜色、字体、控件高度、间距、圆角、焦点与基础动效值，仅在`.guest-experience`内生效。宾客端不用后台Ant Design主题，不修改全局body或后台组件。
- `web/src/checkin/checkin.css`：签到画幅、占位影像、表单、状态与响应式。桌面有宽度边界，手机采用自然页面滚动；没有固定650px画幅或覆盖输入的底部按钮。几何与字号使用局部命名token；600px媒体阈值因原生CSS限制明确保留。
- `web/src/checkin/Checkin.view.tsx`：保留入口、姓名表单与结果的清晰职责。原生form支持回车；输入法组合期间不触发回车提交。初次进入不主动弹键盘，空姓名聚焦输入，真实响应后聚焦结果阅读区域，下一位再聚焦姓名。姓名/错误提示可换行，状态用图标与文字共同表达。减少动态效果时取消入场与旋转。
- `usePublicCheckin.ts`、API、路由、权限、服务端和shared契约没有修改。没有增加请求库、判重逻辑、轮询或业务组件框架。

## 状态与恢复

| 原有状态 | 新视图 |
| --- | --- |
| idle | 姓名输入、简短核对说明与登记动作 |
| saving | 禁用输入/按钮、提交中文字与aria-busy |
| done | 登记已提交，明确“工作人员确认后，才算完成签到” |
| dup | 已提交过，无需重复登记，指向现场核对 |
| confirmed | 已完成签到，来源为服务端结果 |
| inactive | 明确驳回/撤销，提供现场协助与重新填写入口 |
| error | 原Hook错误原文、保留输入与重新提交 |

姓名不是身份依据。保留既有submissionKey、请求锁与localStorage恢复，失败和刷新后仍沿用原键；下一位才清理原尝试。前端只表达状态，不根据姓名判断同一宾客，不把待核对视为已确认。

## 实际验证

Node24下`pnpm check`通过：全项目lint零错误，既有92条服务端/测试警告保留；前端零警告，6项分层规则测试、TS7类型检查、118项业务测试及生产构建通过。修改范围Prettier与git diff空白检查通过。

真实React构建通过独立本机模拟服务验收，没有请求生产后台、连接数据库或写真实签到记录：

- 空白姓名显示原校验并聚焦，首次有效请求前没有签到请求。
- 请求姓名去除首尾空格；失败保留原输入。刷新恢复姓名，重试完整载荷及submissionKey与失败前一致。
- 提交中输入和按钮均禁用；结果区获取阅读焦点。
- 待核对、重复提交、已确认、已驳回和已撤销分别验证。
- 429显示服务端文案并保留姓名，不伪造成功。
- 下一位清空姓名并聚焦；即使再次输入同名，也使用新提交标识。
- 回车正常提交。输入法组合防护已实现，真实手机输入法仍需设备验收。
- 320×568、390×600、390×720、844×390横屏及1280×720检查无横向溢出；28字长姓名换行，错误/按钮/帮助文字不重叠。短窗口内容可以自然滚动。
