## 二维码与版式

- 复用 qrcode 编码与 Sharp 本地渲染，使用 H 纠错和四模块静区。独立码使用整数像素模块；物料码按确认的画框等比适配，并在完整静区之外增加圆角白色外框。码点圆润，三个定位角保留清晰轮廓。
- 猫头来自已确认的本地透明 PNG。中心留白与功能模块的整个单元边界做避让，必要时选择更高版本，避免长链接把猫头叠到校正图案上；尺寸不足时报错，不输出被压坏的码。
- 三份 SVG 是各自独立的固定像素构图，保留确认的照片圆角、文字大小与留白。图稿内几何属于输出模板，不作为页面间距推广；颜色/字体由 `ARTWORK_TOKENS` 统一，位图尺寸由服务端与 shared 的输出规格管理。
- 日期、新人名字、开席时间和地点读取 wedding 配置，文字 XML 转义。未知厅位、联系人和坐标没有被加入图稿。
- 本机、示例地址、IP 与非 HTTPS 目的地会标为预览，图片写明“地址未就绪，请勿分发”。该分类不证明公网可达，域名确认后还必须人工验收落地页。

## 文件与限制

本机样张在 `outputs/`，通用分享海报编码 `/invite`；它是预览示例，不冒充某位真实宾客的专属邀请。正式单人接口继续按宾客 token 生成。PNG 与 ZIP 中含用户授权照片，按私人婚礼资料管理。

桌牌为 A5 比例；导视为 600 × 900mm 比例预览，现有照片放大后不等于印刷高清原片。当前为 RGB，不含 CMYK 转换、出血或裁切标记；需先确认印厂尺寸、材质和纸样。300 ppi 是输出密度，不代表照片的有效细节达到 300 ppi。

Dockerfile 增加 Noto CJK，SVG 提供对应字体后备，避免依赖本机中文字体。本机没有 Docker，因此 Linux 容器的构建与字体外观尚未实测，部署验收必须覆盖。

下一项：宾客端整体联调，请柬 → 回执 → 自助签到 → 后台核对；重点检查身份隔离、失败恢复与状态衔接。对外域名、微信/手机扫码及印厂核样保持待确认。
