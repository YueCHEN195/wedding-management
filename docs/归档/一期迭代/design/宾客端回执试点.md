## 本轮实现

- 是否出席采用原生单选分段样式，保留键盘操作与可见焦点。人数用带边界禁用的步进器，儿童包含在出席总人数内；切换暂未确定或缺席后隐藏人数，但保留当前草稿。
- 专属请柬显示受邀姓名，不允许重命名；通用请柬输入姓名，并提示本浏览器恢复及换设备限制。缺少姓名时定位输入框，不发送请求。
- 保存期间禁用表单，并在功能 Hook 中增加同步提交锁。失败用行内提示，保留姓名、人数、意向和留言；修改凭证失效沿用服务端错误，不绕过身份关联。
- 本次成功响应生成可核对的回执完成页。初次加载此前回执只恢复编辑内容，不将尚未保存的修改展示成成功。完成页展示服务端返回的数据，支持再次修改及返回请柬，保持当前上下文。
- 继续原生页面滚动，无额外表单内滚动。减少动态偏好下取消自动平滑定位。

## 工程边界

`useInvitation` 管理请求、保存锁、错误和成功响应；`RsvpForm.view` 管理表单、结果切换及焦点；`RsvpAttendance.view` 和 `RsvpReceipt.view` 分别承载人数/意向与完成页。文案和样式留在 invite 功能目录，复用 guest 语义 token，不新增全局基础组件。

删除无调用的旧 `invitationStyles.ts`。没有修改 API、路由、服务端校验、编辑凭证、人数上限、同名关联或保存规则；暂未确定/缺席仍按原约定提交零人数。

## 移动端操作区补充（2026-10-21）

短屏不能保证完整表单在一屏内显示。本轮改为手机端 Grid 两行：唯一的阅读滚动区 + 独立底部操作区；没有通过 sticky/fixed 按钮覆盖输入区域。桌面保持原文档滚动与表单内按钮。

- 首屏没有常驻底栏；进入内页后显示“填写回执”。展开回执后切换为保存按钮，通过原生 `form` 属性提交同一个表单，复用同一保存锁、校验和错误状态。正文同类按钮在底栏启用时隐藏。
- 成功页收起底栏；再次修改恢复保存操作；返回请柬折叠回执但不卸载内容，入口显示“查看或修改回执”。失败定位到错误，空姓名继续聚焦姓名框。
- 底栏和内容使用原 guest token，预留底部与横屏左右安全区。600px 为既有宾客断点；960px 宽且 500px 高以内为手机横屏例外，原生媒体条件不能引用 CSS 自定义属性。
- `useInviteViewport` 只负责阅读位置和可视高度；没有新增业务状态或请求。监听浏览器可视区域的 resize，编辑时可视高度比布局高度减少超过命名阈值 120px 时收起底栏，恢复原表单末尾按钮；缩放时也使用原按钮。不支持 VisualViewport 时，文本聚焦期间采用同样保守回退。

该适配依据 [VisualViewport 文档](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport) 与 [Chrome 对键盘视口行为的说明](https://developer.chrome.com/blog/viewport-resize-behavior)。120px 是区分普通浏览器工具栏变化的启发式阈值，不是通用键盘检测承诺；布局视口也随键盘缩小的浏览器仍采用分行布局，底栏不会覆盖阅读区。

本地模拟 API + 真实 React 构建验证：320×568、390×720、844×390 下操作按钮在视口内、阅读区下沿与操作区上沿一致、没有页面外层纵向滚动或横向溢出；1280×720 下底栏隐藏，原按钮及页面滚动保留。覆盖必填定位、失败输入保留与错误聚焦、慢保存禁用、成功收起、再次编辑、返回请柬及滚回封面收起底栏。Node24 全量检查通过，122 项测试与 6 项规则测试通过，前端零警告，既有 92 条服务端/测试警告保留。

此处的短窗口测试不等同于真实软键盘、缩放、刘海安全区和微信内置浏览器验收；这些仍须手机验证。没有修改业务 Hook、接口或写入真实回执。
