# 后台设计规范：深侧栏 · 珊瑚

更新日期：2026-10-23。本文只保留当前设计约束。逐轮实施及当时截图见[历史归档](../归档/README.md)，组件责任见[公共UI边界](公共UI边界.md)。

## 视觉与Token

铜青导航、珊瑚选中、暖白内容、浅暖核对区、暖棕主操作。少线条不等于无边界：输入、表格行、固定操作区保留阅读所需的边界，避免层层描框。

- 品牌、语义色和Ant Design控件token以 `web/src/admin/theme.ts` 为唯一维护源；手写布局用 `tokens.css`。
- 命名token管理颜色、间距、字级、圆角、高度、阴影、滚动条及断点等设计值；采用4/8间距，不在页面散落新hex或magic number。
- 功能列宽、布局比例和模板几何可用有说明的命名常量；不把页面专属token提升为全局。
- 状态同时用文字/图标和颜色表达。已出席为成功语义，已回执为信息语义；已撤销/作废明确失效，不能仅变灰。
- 控件覆盖default、hover、focus、disabled、error和loading；使用原生键盘与可见焦点。

## 布局与滚动

普通后台页面由Content承担纵向滚动。现场审核为明确例外：占满Content剩余高度，桌面26:74 Grid显示待审队列与宾客名单，模块内部滚动；核对及手工补录从右侧Drawer展开，不常驻挤占数据区。

Viewport → AppLayout → Content → Workbench → Module高度链清晰；中间flex/grid节点设置 `min-height:0`、`min-width:0`。工作台外层不额外纵向滚动，表格固定表头和分页。小屏上下重排模块，保留必要操作，不缩小字体强塞桌面布局。

Drawer/Modal采用原生Header/Footer与独立Body滚动。保存按钮通过Form关联提交，不用覆盖输入区域的sticky Footer；抽屉不超视口。细滚动条低干扰但可发现、可键盘操作。

## 列表与操作

- 编号在姓名前辅助识别，同名按编号核对。长文本单行省略并提供Tooltip，常规表格行高保持一致。
- 独立业务属性分列；邀请/回执和出席状态不能混为一个状态值。
- 主操作明确；高频更正直接可达，历史、归档等低频动作放更多菜单。已出席宾客的菜单遵循产品规则，仅归档和操作记录。
- 每个数据表提供手动刷新，位置与该表或模块工具区对齐；不能挤入主操作或任意悬浮。
- 明确区分初次加载、真实空数据、接口失败和上次缓存数据。现场空态位于Table内部，在可视表体居中，不能用外部覆盖层冒充表格内容。
- 查看详情、保存和刷新尽量保留搜索、筛选、分页；归档/作废等范围变化不能误导为记录被永久删除。

## 表单与反馈

原因输入复用ReasonInput，外部传入快捷原因；Tag未选中为灰底圆角，保留选中、禁用和键盘状态。错误定位优先使用Form原生能力，礼金提交失败滚动到首个错误并聚焦。

保存失败保留输入，版本冲突展示可采取的恢复动作；保存期间禁止重复提交和关闭。未保存保护只用于丢失输入或真实风险，不给常规可逆动作添加确认。

成功使用自动消失toast，普通说明用简短helper text；未解决的错误、冲突和警告留在相关操作区域。真实数据缺失显示未知或未记录，不伪造金额、人数或操作人。

## 页面专属表现与验收

仪表盘可使用克制入场、图表展开和品牌分区；业务表单不沿用持续装饰动画。系统减少动态偏好优先，不能用数字滚动制造中间假值。登录品牌构图仅作用于登录容器。

每次布局/交互修改用真实React验证桌面、短窗口、窄屏、长中文、同名、空值及失败/焦点状态。已有测试结果集中于[一期测试报告](../测试/一期测试报告.md)，历史截图不作为当前页面验收结论。
