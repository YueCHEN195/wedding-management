# 深侧栏 · 珊瑚 / 实施记录

现场审核以“第四轮：核对抽屉与通知”为准；宾客管理以“第五轮：宾客管理与交互准则”为准；礼金管理以“第六轮：礼金管理与账目核对”为准；回执管理以第七轮为准；公共组件的最新归属见[公共 UI 边界](公共UI边界.md)。前几轮内容保留为实施记录。

## 已确认方向
铜青侧栏、珊瑚选中项、暖白内容区、浅暖核对区、暖棕主操作。少线条不是零线条：输入边界、表格行和固定操作区按阅读需要保留，避免模块层层描边。

## Tokens
实际主题来源：web/src/admin/theme.ts，后台Provider统一注入。宾客邀请和扫码页面不使用此Provider，保持原视觉。

- 操作：#824e40；hover #98604e；active #693d32。
- 导航：#283f3e；选中 #e9a182 + 深色文字。
- 背景：#faf7f3；容器 #fffefd；核对区 #f7eee7。
- 正文 #3f3934；次级 #786d65；输入边框 #d7ccc3；分隔 #ece5de。
- 成功 #28645b；警告 #8a611c；错误 #b52d43；信息 #395e89。文字/图标与颜色同时表达含义。
- 标题24、区标题16、正文14、次级12–13px；数字沿用组件的可读排版。
- 间距4/8基准：页面24、窄屏16、表单16、字段间距16、工作区20。
- 控件36/小28/大44px；现场按钮保留44px。常规圆角6、工作区与弹层8px。
- 默认无按钮阴影；浮层轻阴影；动效160–200ms。后台尊重减少动态偏好。

## 组件与线条
Input/InputNumber/Select/DatePicker统一高度、圆角、字体；保留细边框，聚焦使用主题色和光圈。校验文案和原有解析器不变。后台操作按钮分主、默认、文字、链接和危险；不是每个区块都设置主按钮。

Table使用浅暖表头、淡水平行线、无表头竖分隔；hover暖底。先利用原生组件token，不创建包装整个Table的大型抽象。

Drawer统一24px内边距和16×24px footer。后续新增编辑Drawer应使用原生footer插槽，Body独立滚动，不把按钮塞进表单正文。现有详情Drawer与业务Modal本轮只继承主题，未改成新业务流程。

## 布局与滚动
AppLayout固定视口高度；Header不滚动；Content flex:1、min-height:0、overflow:auto，承担唯一页面纵向滚动。侧栏仅在导航超高时独立滚动。审核队列不再嵌套纵向滚动；窄屏队列横向排列。主表单沿用页面滚动，不增加新的内层滚动区。

## 本轮范围
已接入全后台基础主题、Layout样式、现场审核页视觉。退出改为原生Button以支持键盘，原有离开保护保留。没有修改API、DTO、路由、权限、金额/人数解析、签到提交或更正逻辑。

现场审核仍是现有队列+核对表单。本轮不是最终预览的全功能统一工作台：全宾客索引、跨实体汇总、操作人来源需要独立设计数据组合，不能用模拟数据写入实际产品。公共FilterBar、StatusTag和DrawerForm尚未新增，待第二个稳定复用场景确认后再抽象。

## 验证
类型检查、生产构建通过。使用项目要求的Node24运行105项测试全部通过（默认Node20运行时数据库测试异常退出，切换正确运行时后通过）。使用浏览器模拟API检查实际React页面，验证不连接真实业务数据。

## 第二轮：统一现场工作台

已新增 `GET /api/guests/workbench` 只读投影，不改变旧名单/详情接口、数据库结构及写入规则。查询按宾客ID组合最新回执、有效签到与有效礼金；未关联档案的待审提交按提交ID独立展示，不按姓名合并或提前建档。归档档案不进入当前名单，关联归档对象的待审仍在队列中按原流程处理。

- 全部宾客、待审核、已签到、未签到四个页签；姓名/分组搜索、归属筛选、分页。
- 左侧队列与名单，右侧核对；不足1200px回流为单列，选中对象时滚动到核对区；队列默认最多3条，可展开。
- 未签到档案可带入姓名到原手工核对流程，仍需明确辨认同名对象。待审行使用原确认流程。已签到行打开详情，不重复签到。
- 管理员详情抽屉可修改姓名、分组、归属与备注，使用现有PATCH及校验；固定Footer，关闭未保存提醒、刷新保护、失败保留输入。
- 已签到详情提供原签到记录/人数更正、礼金登记/更正入口，不在新表单里绕开更正原因和版本保护。
- 工作人员不返回礼金汇总、私人备注、电话或邀请凭证；不调用管理员统计接口。
- 操作人：原签到确认没有完整持久化此字段，因此详情显示“未记录”；不以礼金操作人冒充签到确认人。
- 金额为有效礼金总和，作废记录排除；历史实际人数缺失继续显示待补记，不能用预计人数补齐。
- 表格水平行线与输入边框保留；保存摘要/按钮随正文滚动，避免窄工作区中遮挡金额与备注输入，不增加表单内部纵向滚动。

验证：类型检查、生产构建通过；Node24全量110项测试通过，新增5项只读投影测试覆盖同名隔离、未知人数、有效礼金、分页筛选、鉴权与工作人员字段白名单。浏览器拦截全部API后使用虚构数据检查表格到核对、草稿保护、抽屉PATCH、390px无整页横向溢出及工作人员字段裁剪，没有访问真实业务数据库。

当前范围仍为现场审核试点；其他页面尚未逐页改造。更正页面的搜索未自动带入宾客ID，仍在原页面手动筛选；未来若增加深链参数，应单独评审路由/状态约定。没有虚构实时抢占锁或离线草稿持久化能力。


## 第三轮：固定高度工作台

按用户反馈改为左右1:1 Grid。Content在审核路由禁用外层滚动，Workbench填满剩余高度；左侧队列/名单分配固定比例，右侧标题与保存区固定，正文独立滚动。表格使用新增的轻量ViewportTable公共组件，测量可用高度生成原生Ant Table的scroll.y，分页独立固定；不在表格外再套纵向滚动。空态覆盖层以可视表体为基准水平/垂直居中，较矮容器隐藏插图保留文字。滚动条为细暖灰色，保留可发现性。小于768px时模块纵向重排于工作区滚动容器中，桌面一屏布局不强套到手机。

新增tokens.css统一几何与表面token；审核页旧的重复样式覆盖已合并。主题颜色仍来自theme.ts。根目录AGENTS.md固定了复用、业务边界、最新文件读取、token、滚动及验证规则；普通页面仍沿用Content滚动，审核工作台为明确例外。

扫码入口改为“扫码 / 代登记”：二维码默认编码当前站点/checkin，可输入手机可访问的完整地址，支持打开签到页。检测localhost/环回地址时提示使用局域网IP或部署地址。代填姓名复用api.publicCheckin.self，仍经过原有速率限制、姓名核对及提交幂等；只加入待审，不直接确认或记账。失败保留姓名和提交标识，成功刷新队列与名单，不更换当前核对对象。登记下一位时明确重置标识。未变更服务端业务代码。

扫码Modal固定Header/Footer，内容超高时只滚动Body。手机扫码需要能实际访问电脑的网络地址；浏览器不能替代网络部署配置。

验证：Node24全量110项测试、类型检查、生产构建、diff空白检查通过。模拟API浏览器实测1440×900与1280×720左右等宽、外层无滚动、队列/表单独立滚动、保存区在视口内；空态中心偏差小于1px；390px无整页横向溢出。模拟首次代登记失败后重试，两次请求提交标识相同，成功立即出现待审项并保留原核对草稿。扫码URL和代登记写入均用虚构/模拟数据验证，未向真实账目写入测试数据。


## 第四轮：核对抽屉与通知

按最新评审将核对及手工补录从常驻右侧表单移到原生Ant Design右侧Drawer。主工作区以26:74 Grid展示队列与宾客名单；保持固定高度与模块内部滚动，优先把屏幕空间交给数据。小屏将两块数据模块上下排列，表单仍在抽屉中展开。

Drawer宽度token为min(600px,100vw)，使用原生Header/Footer固定，Body独立滚动。Footer按钮通过原生form关联到表单，支持正常验证及键盘提交。关闭、遮罩和Esc沿用原未保存保护；保存期间禁止关闭。失败保留输入和同一提交标识，保存成功关闭抽屉并刷新数据。门户复用与Shell相同的CSS变量源，避免抽屉丢失主题token。

签到保存、代登记和宾客档案编辑成功均使用统一4秒toast，不再在页面放置需要手动关闭的成功Alert。普通说明采用helper text；同名冲突、保存结果不明、网络失败等仍在相关操作区域保留可采取行动的提示。已签到详情的普通说明也改为次级文字。

根目录AGENTS.md已同步当前布局和通知策略。服务端接口、校验及记账流程未改动。

验证：类型检查、生产构建和110项测试通过。模拟API验证主页面无纵向溢出、抽屉固定Footer、未保存关闭提醒、失败输入保留、相同内容重试、成功后关闭抽屉、toast自动消失、仅签到的手工补录、代登记toast及390px抽屉宽度。模拟写入未访问真实业务数据。

## 第五轮：宾客管理与交互准则

迁移管理员宾客管理与工作人员宾客查询，沿用已确认主题。常规名单仍由Content负责页面滚动；不把现场审核的一屏工作台规则强加到档案管理。新增/编辑/详情使用右侧原生Drawer，Header/Footer固定，Body独立滚动，窄屏字段重排为单列。

表格评审调整：邀请/回执状态与是否出席拆成独立列；姓名、ID保持同一行，称谓保留在Tooltip与详情中。名单使用Ant Design原生small密度，数据行统一56px命名token；长姓名、分组、手机号、备注和工作人员回执摘要单行省略，Tooltip展示完整内容。工作人员历史范围的归档标记独立成列，不挤占姓名。模拟长中文、换行备注及混合归档数据，1440px、1280×720与390px下每行实测56px，姓名键盘聚焦与备注悬停提示正常。

- 页面保留一个“新增宾客”主操作；导入、导出与逐行低频操作放在次级工具区。常用搜索直接展示，分组/归属渐进展开，并显示可移除筛选条件。
- 切换当前/已归档/全部范围保留筛选；新增和保存后保留列表条件及分页。详情与编辑在同一抽屉切换，减少关闭再打开。
- 按ID编辑，先读取最新档案再填表；同名显示ID辅助辨认。读取失败禁止保存并提供重试，异步旧响应不能覆盖新打开的档案。
- 保存失败保留输入，成功使用4秒toast；关闭、导航与刷新保护未保存输入。保存期间禁用关闭，避免结果不明。
- 导入防重复点击，部分成功逐行显示失败原因；无法确认结果时提示先核对名单。归档继续复用原影响预览、原因及确认流程。
- 加载失败与真实空名单分别表达，支持重试；缺失实到人数显示未记录，不推算为0。作废礼金继续排除有效合计。
- 工作人员沿用既有受限接口，不增加电话、私人备注、邀请凭证或礼金数据，也不增加管理操作。

稳定复用部分抽出PageHeader、GuestListTools、AdminDrawer和useUnsavedChanges；现场审核的档案编辑复用同一未保存保护。没有新增通用业务引擎或更改服务端规则。项目AGENTS.md新增交互评审规则：减少重复定位、渐进展开、明确反馈、失败恢复与必要确认。

验证：Node24类型检查、生产构建、110项测试及diff空白检查通过。真实React页面拦截API验证1440px桌面、1280×720短窗口、390px窄屏；覆盖筛选保留、同名按ID编辑、读取最新备注、保存冲突后原输入重试、详情/编辑同一抽屉、固定Footer、新增后列表上下文、归档原因、导入部分失败、网络失败与空态及工作人员视图。现场审核抽屉回归检查通过。预览使用虚构数据，没有向真实签到/礼金记录写入测试数据；真实Excel解析、二维码资源和网络部署本轮未额外做端到端验证。


## 第六轮：礼金管理与账目核对（2026-10-19）

礼金页沿用“深侧栏 · 珊瑚”，普通列表由 Content 滚动。复用 PageHeader、TableText、StatusTag、AdminDrawer、原生 Table/Tabs/Form 与共享筛选布局；页面专属实现位于 gifts 目录，不增加万能 FilterBar、DataTable 或业务表单框架。

- 汇总改为紧凑信息带，标明“当前筛选内的有效礼金”，只展示服务端返回的汇总与方式分项，不在前端重算、不把未知汇总补为零。工作人员仍无汇总与管理入口，服务端数据权限未改。
- 搜索与收款方式直接可达，已应用条件可移除；切换有效/已作废/全部范围保留搜索和方式，筛选变化回到第一页，保存后保留列表上下文。搜索输入与已应用条件分开，清除有明确入口。
- 姓名与礼金编号同一行，关联宾客 ID 独立列；金额右对齐、等宽数字，作废金额划线并有文字状态；方式直接用文字。名单行高为礼金页专属 56px，长姓名和备注使用 TableText 的省略与 Tooltip，时间和操作保持单行。

- 复用 useUnsavedChanges，为已填写草稿提供关闭、导航与刷新保护；空白表单可直接关闭，保存中禁止关闭。成功仍使用统一自动消失 toast，不常驻成功提示。
