- 原设计：`guest-exploration/noir-refined.html`、`refined.css`、`refined.js`；物料以其 `output-studio` 中的最终输出样张为准。
- 已确认的后续调整优先于早期稿：猫头二维码、夜景签到桌牌、无边框的打开入口、全幅揭幕结束，以及手机单一阅读滚动区与独立底部操作行。

## 有意保留的实际产品适配

- 回执仍在请柬内渐进展开，婚礼安排与相册保留；不是强制翻页的独立演示屏。
- 手机操作行与阅读区分开占位，保存与填写入口不会覆盖输入框；软键盘/缩放时沿用原先回退策略。
- 专属请柬的姓名是只读身份，通用入口保留姓名编辑与恢复说明；不把演示稿的可编辑姓名机械搬入专属请柬。
- 保存回执显示真实保存结果，签到提交后明确等待工作人员核对。原稿中的演示成功、演示提示不进入真实业务。
- 保留完整地址、导航门店核对、加载失败、失败输入、重试、原幂等标识和未保存保护。
- 签到结果保留较高的紧凑照片区域，保护两人面部；不回退为原演示稿仅 88px 的裁切。
- 色板、照片圆角 18px、输入/按钮圆角 12px 与暖白底色已与确认稿一致，无须更换主题。

## 工程边界

只修改宾客端视图、局部样式和现有视口 Hook 的展示型滚动变量。品牌图形复用 guest 局部样式，不增加通用组件框架。新增几何与动效值均为命名 token；后台主题、API、权限、身份关联、签到与回执规则不变。未向外部服务上传照片，未部署或推送代码。

## 验证与限制

使用本机隔离的模拟接口和真实 React 生产构建检查，未写入真实宾客、回执、签到或礼金。

- 390×720：封面、内页、导航弹层、回执表单与结果、签到表单与待核对状态实际渲染正常。
- 320×568：回执保存操作行在可视区域内，页面无横向溢出，阅读区与操作行边界不重叠。
- 844×390：内页定位完成后，阅读区高度约 316px，操作行约 74px，外层高度 390px，没有额外页面纵向滚动。
- 1280×720：内页标题保持 23px，文档宽度限制与自然页面滚动保留，无横向溢出。
- 保存失败保留留言，重试成功才进入结果页；重新修改带回留言，返回操作不清除输入。返回封面后滚动位置为 0，焦点回到打开入口；进入内页后的滚动过渡进度为 1，封面文案按原稿淡出。
- Node24 下 `pnpm check` 通过：前端零警告、6 项分层规则测试、130 项业务测试、TS7 类型检查与构建通过；原有 92 条服务端/测试警告保留。修改范围已格式化，`git diff --check` 通过。
