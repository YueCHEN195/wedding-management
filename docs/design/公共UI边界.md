# 公共 UI 的归属与复用边界

沿用“深侧栏 · 珊瑚”。本文件约定现有实现的责任边界，不代表所有旧页面已经完成视觉迁移。修改前仍应读取最新调用方。

## 项目统一什么

| 来源 | 负责内容 | 不负责内容 |
| --- | --- | --- |
| `web/src/admin/theme.ts` | 品牌和语义色、Ant Design 原生控件的尺寸、状态、表格、Tabs、Drawer、Modal token；共享 Portal 品牌变量；4 秒反馈时长 | 业务状态判定、权限、页面 Grid 比例 |
| `web/src/admin/tokens.css` | 手写布局使用的间距、文字、圆角、控件高度、滚动条、筛选宽度和抽屉宽度 | 宾客数据行高、二维码尺寸、审核队列比例与专属色块 |
| `AdminLayout` / `admin.css` | 视口高度链、导航、Header、普通页面 Content 滚动，以及审核路由的明确例外 | 各功能的查询参数、编辑状态 |
| `AdminProviders` | 主题、语言及原生静态反馈配置；未指定时长的后台 toast 默认 4 秒 | 把保存失败或冲突统一变成短暂 toast |

品牌值以 `theme.ts` 为准；CSS token 为手写区域提供命名尺寸。两者调整时检查对应原生控件与自定义布局，不在业务页直接覆盖整套控件。CSS 媒体查询暂沿用现有固定阈值：CSS 自定义属性不能直接用于原生媒体条件，此轮不另建预处理体系。

## 已有组件如何复用

| 组件 / 样式 | 约定 |
| --- | --- |
| `PageHeader` + `page-header.css` | 页面标题、简短说明、主操作；样式随组件加载，不依赖宾客页 |
| `TableText` + `table-text.css` | 长文本单行省略和原生 Tooltip；不决定数据格式、列宽或空值的业务含义 |
| `filter-bar.css` 的 `admin-filter-row` | 搜索、Select、操作的排列及宽度；只共享布局，不持有筛选状态 |
| `GuestListTools` + `guest-list-tools.css` | 管理员与工作人员宾客筛选的稳定业务模式；草稿、提交时机、权限入口继续按原约定处理 |
| `AdminDrawer` + `admin-drawer.css` | 原生 Header/Footer、独立 Body 滚动、Portal token；合并调用方 Body class，不丢失公共滚动样式；`admin-drawer-footer` 提供常规操作排列 |
| `ViewportTable` | 仅用于有明确高度边界的模块；原生固定表头、独立分页、按可视表体居中的空态；普通列表继续直接用 AntD Table |
| `StatusTag` | 静态状态的低饱和语义色和图标；调用方传文字与 `neutral/inactive/pending/info/success/error` 语义，不传颜色 |
| 原生 Modal / Form / Table / Tabs | 优先继承 `theme.ts`，不为套样式新增同名包装或万能业务组件 |

`StatusTag` 不推导业务状态、汇总或权限。未审核与已驳回分别表达等待和错误，已撤销、已作废使用失效语义；每个标签有文字，图标不重复朗读。筛选条件继续使用可关闭的原生 Tag，支付方式、角色等分类不套用成功/失败状态。

编辑草稿、失败保留、未保存保护、版本冲突和保存后的缓存刷新仍属于功能 Hook。公共 Drawer 不能自行拦截所有关闭、强制保存或增加确认步骤；长表单通过原生 Footer 和 Form 关联提交。

## 输入查询与防抖

输入即查的请求复用 `admin/hooks/useDebouncedValue.ts`，默认延迟由命名常量 `SEARCH_DEBOUNCE_MS` 统一为 300ms；不新增依赖或查询框架。Hook 同时返回稳定值与等待标记，输入 A → B → A 也要重新等待，不能因回到缓存中的值而提前请求。

- 已应用于新增礼金姓名联想、现场手工核对姓名联想、审核名单即时搜索。原有回车/点击搜索、Select 筛选、分页、已知待审记录核对、保存与重试不额外防抖；审核名单清空时立即恢复查询。
- 姓名联想在中文输入法组合期间不请求拼音中间值，选字完成后再等待；空姓名不查询。关闭或卸载时清理尚未触发的计时器。
- 候选 query key 始终对应当前姓名，等待时不显示旧候选或“没有同名”结论，表单选择随姓名变化清空。姓名尚未稳定、查询尚未完成或失败时，按钮及表单提交入口都不能绕过核对；礼金、签到的原有解析、校验、按 ID 关联和幂等规则不变。
- 姓名等待与实际离开对象分开处理，输入法状态切换不能重置已手填人数。已发出的请求可能继续完成，其结果按原 query key 隔离，不能覆盖新姓名的候选；此轮没有修改 API 客户端来强行中断请求。

2026-10-19 验证：真实 React 页面拦截接口，连续三段输入只查询最终姓名；快速返回旧姓名仍等待完整延迟；覆盖输入法、清空/关闭、迟到旧响应、等待期间直接提交表单、同名 ID、手工核对及显式点击待审项立即查询。原礼金冲突/失败重试、签到幂等/后台刷新人数保护回归通过。Node24 全量检查、前端零警告、6 项规则测试、110 项业务测试和构建通过；既有服务端/测试警告保留，无真实账目写入。

## 页面保留什么

- `guests.css`：名单 56px 行高只作用于 `.guest-list-page`；媒体宽度、预览最大高度只作用于 `.guest-media-dialog` / `.guest-import-report`，Portal 显式带类名。
- `review.css`：26:74 桌面 Grid、窄屏模块分配和队列色块只作用于 `.review-workbench`；保存摘要色块只作用于 `.review-drawer`。核对抽屉复用公共宽度，详情抽屉复用较窄的 480px 宽度，均不超过视口。
- 各功能继续定义业务列宽、字段组合、轮询策略、搜索生效时机、筛选重置与保留方式；不能通过视觉收口暗改这些交互。
- 普通页面使用 Content 滚动。现场审核继续一屏工作台、模块内部滚动；编辑在右侧抽屉，不恢复常驻表单。

新增公共组件前先找第二个稳定场景。暂不建立 `DataTable`、万能 `FilterBar`、`ModalForm` 或 `DrawerForm`；仅外观相似不构成统一业务 API 的理由。
