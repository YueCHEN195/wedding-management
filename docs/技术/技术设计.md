# 一期架构与实现说明

更新日期：2026-10-23。以当前代码说明实现，不再保留选型草案、云服务报价或逐轮补丁。业务规则见[需求文档](../产品/需求文档.md)和[数据操作与保留规则](../产品/数据操作与保留规则.md)。

## 运行结构

单一工程：React SPA → 同源Hono API → SQLite/WAL。开发时Vite代理 `/api` 到3000端口；生产时Hono托管 `web/dist` 并提供SPA回退。Docker Compose配置一个应用服务及Caddy，SQLite挂载到宿主机 `data/`。

依赖以根 `package.json` 和锁文件为准：TypeScript 7、Node >=24、React 19、Vite 8、Ant Design 6、React Query、Hono、Drizzle、better-sqlite3、Zod；二维码用qrcode，图像用Sharp，ZIP用JSZip，Excel用ExcelJS。自动化使用Node内置测试运行器；Playwright独立安装在 `tooling/e2e/`。ESLint/Prettier与TS6独立位于 `tooling/eslint/`，应用保持TS7。

## 分层与权威来源

| 位置                                           | 职责                                             |
| ---------------------------------------------- | ------------------------------------------------ |
| `server/index.ts`                              | 迁移、路由注册、成功写入通知及生产静态资源       |
| `server/routes/`                               | HTTP解析、权限、调用服务、响应字段选择           |
| `server/services/`                             | 签到、礼金、生命周期事务、现场只读投影、物料输出 |
| `server/lib/validation.ts`                     | 运行时输入校验及并发编辑前置条件                 |
| `server/lib/dto.ts`                            | 输出DTO，含工作人员字段白名单                    |
| `server/db/schema.ts`、`server/db/migrations/` | 当前模型和增量迁移                               |
| `shared/`                                      | DTO、数值解析、校验边界、婚礼及物料配置          |
| `web/src/api/`                                 | 会话、请求、共享查询                             |
| `web/src/admin/<功能>/`                        | 页面组合、功能Hook、视图                         |
| `web/src/invite/`、`checkin/`                  | 请柬/回执与自助签到                              |

复杂页面由功能Hook集中请求、mutation、缓存刷新及流程状态；视图保留原生Form交互。服务端决定身份、权限、业务状态及汇总，前端不得按姓名猜关联或重算记账结果。具体边界见[代码质量规范](代码质量规范.md)。

## 数据与持久化

| 表                    | 用途与关键字段                                                    |
| --------------------- | ----------------------------------------------------------------- |
| `users`               | 登录账号、bcrypt密码摘要、admin/staff角色                         |
| `guests`              | 独立ID、可重复姓名、邀请token、邀请/回执状态、归档时间            |
| `rsvps`               | 档案关联可空；预计人数/儿童、留言；通用回执私有凭证摘要           |
| `checkins`            | 待审/已确认/已驳回/已撤销；实到人数及儿童可空，历史未知保留NULL   |
| `checkin_submissions` | 提交标识摘要、规范化内容摘要、原签到ID；持久化重试映射            |
| `gifts`               | 整数分、方式、可空宾客/签到关联、作废时间、版本、独立登记重试摘要 |
| `operation_logs`      | 操作对象、动作、原因、操作者、前后值与时间                        |

完整字段以schema和迁移为准，不另维护容易过期的数据字典。金额存整数分，页面以共享解析器处理元；时间存毫秒，DTO格式化后提供界面使用。礼金、签到状态与回执独立，不物理删除或解除历史关联。

## 认证、权限与并发

- Hono JWT签名会话通过HttpOnly、SameSite=Lax Cookie传递，当前有效期7天；Secure取决于 `PUBLIC_BASE_URL` 是否HTTPS。生产缺失、空白或开发默认密钥会拒绝启动。
- admin/staff中间件和DTO白名单限制访问。完整回执、统计、导出和管理操作由服务端限制；工作人员现场详情仅保留必要字段，礼金列表不返回汇总。
- 宾客档案及后台回执编辑通过 `If-Match` 核对 `updatedAt`；礼金更正要求 `expectedVersion`、原因及修改字段。
- 自助/手工签到及独立礼金登记保留提交标识。相同操作重试返回原结果，标识复用但内容不同会冲突；新标识不按姓名/金额猜测为同一业务。
- 确认签到、可选礼金及相应审计在事务内写入；生命周期操作先读取影响预览，再提交快照token，事务内重查权限、状态与关联。
- `DELETE`旧业务入口返回409；归档、驳回、撤销、作废通过统一生命周期接口处理。

登录限频、主动撤销已签发会话等旧方案不能当作现成功能；当前限制与部署事项见[上线前待办](上线前待办.md)。

## 接口导航

统一返回 `{ ok: true, data }` 或 `{ ok: false, error: { code, message } }`。JSON分页一般返回 `items/total/page/pageSize`；附件接口返回真实二进制文件。下表为入口导航，字段及限制查对应路由与shared类型。

| 路径                                                         | 说明                                          |
| ------------------------------------------------------------ | --------------------------------------------- |
| `/api/auth/login`、`logout`、`me`                            | 登录、退出、身份                              |
| `/api/guests`、`/groups`、`/:id/detail`                      | 名单、分组、角色裁剪详情                      |
| `/api/guests/workbench`                                      | 按ID组合现场名单、有效签到及管理员可见汇总    |
| `/api/guests/import`、`/export`、`/posters/export`           | xlsx导入、名单导出、批量海报                  |
| `/api/guests/:id/qr`、`/:id/poster`                          | 管理员专属二维码和海报                        |
| `/api/rsvps`、`/:id`                                         | 管理员完整回执列表/单条/修改                  |
| `/api/checkins`、`/pending`、`/candidates`                   | 登录后的签到列表、待审和身份候选              |
| `PATCH /api/checkins/:id/confirm`、`/:id/attendance`         | 确认；管理员/工作人员人数更正                          |
| `/api/gifts`、`/:id`                                         | 礼金列表；管理员独立登记；工作人员可读/更正签到关联单笔           |
| `/api/lifecycle/:entity/:id/preview`、`/:id`、`/:id/history` | 影响预览、状态操作、历史                      |
| `/api/stats/summary`、`/charts`、`/api/export/:type`         | 管理员统计和四类xlsx导出                      |
| `/api/invite`、`/rsvp`、`/:token`、`/:token/rsvp`            | 通用/专属邀请与回执；通用修改凭证不按姓名恢复 |
| `POST /api/checkin/self`、`GET /api/checkin/qr`              | 公开姓名提交和公共签到二维码                  |
| `/api/checkin/materials`、`/display`                         | 管理员物料配置和PNG输出                       |
| `GET /api/events`                                            | 登录后SSE通知，不携带完整业务数据             |
| `GET /api/health`                                            | 服务健康检查                                  |

## 实时与故障恢复

现场审核使用EventSource订阅SSE；成功的业务写入完成后发布变更通知，前端重新获取受权限约束的数据。重连ready时补齐遗漏更新；断线/初次未连通时启用15秒备用刷新，另保留手动刷新。当前通知为进程内监听，不代表已支持多应用实例的跨进程广播。

查询刷新不能覆盖正在核对的人数、明确身份选择和未保存草稿；记录被其他人处理后禁止再次确认。自助签到在localStorage保留失败重试标识；独立礼金草稿不承诺跨刷新恢复。根路由错误页静态加载，动态页面模块失败时提供重新加载与后台替代入口。

Vite按mode隔离缓存并预构建图表依赖；额外开发验证服务使用 `--mode verification`，见[本地开发与验收](本地开发与验收.md)。

## 部署边界

以 `.env.example`、`docker-compose.yml`、`Dockerfile`、`Caddyfile` 为配置依据。应用启动自动迁移，**不自动初始化账号**；`db:seed`会建缺失账号，并在没有宾客时插入示例宾客，既有账号不会因环境变量变化而改密码。

Docker镜像使用Node24及Noto CJK字体；Caddy读取DOMAIN。正式账号初始化、容器构建、HTTPS/SSE、真实素材、备份与恢复的验证不能由本地测试替代。不能把xlsx导出当作完整SQLite备份，也不能承诺运行中的WAL数据库只复制主文件即可恢复。
