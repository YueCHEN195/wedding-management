# 本地构建镜像，再发布到香港服务器

提供两个可双击的 Windows 入口，均构建当前已保存的工作区，包含未提交的修改。不自动提交 Git，不初始化账号，不写入演示宾客。

本文域名及服务器 IP 已替换为占位符，Ubuntu 用户和路径为通用示例。实际部署时使用自己的值，连接配置保存在被 Git 忽略的 `server.local.json` 中。

| 入口                         | 用途                                                        |
| ---------------------------- | ----------------------------------------------------------- |
| 根目录 `build-release.cmd`   | 本地检查、构建 Linux 镜像、生成发布文件夹；用腾讯云网页上传 |
| 根目录 `publish-release.cmd` | 同样先生成发布包，再通过 SSH/SCP 自动上传并更新             |

2026-10-23 本次部署现状：服务器项目在 `/home/ubuntu/wedding-management`，应用通过 `compose.staging.yml` 仅监听本机3000端口，由 Caddy 对外提供 `https://example.com`；域名解析、证书与跳转已验证，见[部署验收记录](部署验收记录.md)。这些脚本只更新已有部署，不负责首次建站、域名注册、开放端口或初始化账号。

## 一、首次准备，只做一次

1. 安装并启动 Docker Desktop，使用 **Linux containers**。等待引擎运行；只有 `docker.exe` 不够。
2. 本机准备 Node >=24、pnpm，并按 README 安装项目依赖。脚本会在缺少独立 ESLint 时执行 `pnpm lint:setup`。
3. 服务器保留原来的 `.env`、`data/`、`docker-compose.yml`、`Caddyfile`、实际使用的 `compose.staging.yml`，不要用本地文件覆盖。
4. 发布前保存文件，建议提交一个明确的 Git 版本，方便追溯。脚本实际构建当前工作区，不只构建 HEAD。

使用 `docker build --platform linux/amd64` 在 Windows 上构建与香港 x86_64 服务器匹配的 Linux 镜像，再用 Docker save/load 传输。Windows 的 `node_modules` 不会被复制进去；`.dockerignore` 排除了本地密钥、数据库、依赖和发布输出。

## 二、最容易上手：双击构建，网页上传，粘贴一行

### 1. 双击根目录 `build-release.cmd`

自动执行完整 `pnpm check`，构建镜像，在不挂载业务数据、禁用网络的临时 Linux 容器里验证数据库迁移与原生依赖，再导出镜像。任何一步失败都会停止，窗口保留错误信息；首次下载基础镜像和依赖可能较慢。

临时检查保留生产模式，在容器进程内生成一次性随机 `JWT_SECRET`，数据库使用 `/tmp/release-smoke.db`；不会读取服务器密钥或将检查密钥保存到镜像、发布包中。线上运行仍使用服务器 `.env` 中原有的密钥。

本地双击入口和 Dockerfile 默认通过 Debian 官方 HTTPS 源安装软件包，APT 网络操作设置30秒超时与3次重试，保留 Debian 签名验证。若本地出现 `apt-get update` 的 `Connection failed`，属于容器到软件源的连接失败，不是项目编译错误，也不会更新线上服务。修复后重新双击即可，之前成功的构建层可继续复用。

需要切换源时可在 PowerShell 运行 `./scripts/deploy/build-release.ps1 -DebianMirror https://mirrors.ustc.edu.cn`，也支持清华的 `https://mirrors.tuna.tsinghua.edu.cn`，但须以本机网络实际可达为准。软件源设置只影响 Debian 包，不会自动修改 Docker Hub、pnpm/npm 或 Docker Desktop 的代理配置。

成功后自动打开 `releases/wedding-日期-时间-随机编号/`：

| 文件                                         | 作用                                    |
| -------------------------------------------- | --------------------------------------- |
| `image.tar`                                  | Docker 镜像，通常明显大于源码包         |
| `release.json`                               | 唯一版本、镜像 ID、架构、镜像包 SHA-256 |
| `update-server.py` / `deployment_support.py` | 服务器更新和数据库备份逻辑              |
| `SERVER-COMMAND.txt`                         | 本次发布对应的一行服务器命令            |

不要修改 `release.json` 或镜像文件名，不要上传尚未生成完成的文件夹。

### 2. OrcaTerm 上传整个文件夹

已登录服务器终端 → 右上角文件夹 → `/home/ubuntu` → 上传 → **上传文件夹**，选择刚生成的 `wedding-…` 文件夹。必须传整个文件夹，不能只传 `image.tar`。

上传后应为 `/home/ubuntu/wedding-…/release.json` 等文件，不要多嵌套一层 `releases/`。

### 3. 复制 `SERVER-COMMAND.txt` 的整行到服务器终端，按回车

无需手敲版本号，类似：

```bash
sudo python3 /home/ubuntu/wedding-20261023-160000-aabbccdd/update-server.py --project /home/ubuntu/wedding-management
```

生成的命令适用于本次 Ubuntu 目录；如项目路径或上传位置变化，先修正路径。

### 4. 等待 `Updated successfully`

先验证上传包、现有应用及数据库挂载，再加载镜像；上述失败不停止旧服务。之后短暂停止应用，生成并验证 SQLite 一致性备份，切换镜像，检查健康接口、登录页及未登录访问限制。

成功后用手机、电脑打开正式 HTTPS 域名，验证登录、请柬、图片和关键只读页面。内部健康检查不代表域名、证书、跨境访问或微信展示都通过。

## 三、配置一次，以后双击自动发布

需要本机 OpenSSH 的 `ssh`、`scp` 可登录服务器，Ubuntu 账号可执行 `sudo -n docker …` 和 `sudo -n python3 …`。网页免密登录不等于本机 SSH 已配置。

1. 复制 `scripts/deploy/server.example.json` 为同目录的 `server.local.json`。
2. 用记事本填写实际 SSH 用户和 IP。下面仅为示例，必须替换 `YOUR_SERVER_IP`，并核对服务器目录：

```json
{
  "target": "ubuntu@YOUR_SERVER_IP",
  "project": "/home/ubuntu/wedding-management",
  "inbox": "/home/ubuntu/wedding-releases"
}
```

3. 验证现有 SSH 登录方式。没有密钥时，需要另行绑定；脚本不会创建密钥、放开防火墙或修改权限。JSON 不保存密码或私钥。
4. 首次 SSH 主机指纹提示须核对后接受，脚本未关闭身份校验。密码登录可能在不同 SSH/SCP 连接中反复询问；已有密钥配合 SSH agent 可减少输入。
5. 以后双击 `publish-release.cmd`，自动检查、构建、上传并更新。失败仍保留本地发布包，可直接改用网页上传，不用重建。

只更新已有 `app` 服务，不改 Caddy、端口、TLS、域名解析和权限。域名配好后仍可使用。

## 四、数据、备份和失败恢复

- 账号和业务数据留在服务器 `data/wedding.db`；密钥仍来自 `.env`。更新无需初始化账号，更不要运行会写演示宾客的 `db:seed`。
- 每次切换前，用 SQLite backup API 创建 `backups/本次版本/wedding.db` 并检查完整性，包含 WAL 已提交内容，不是只复制 `.db`。
- 备份目录记录旧镜像 ID。旧镜像、上传包和备份不自动删除，注意磁盘容量。这只是同机备份，仍需异地副本和恢复演练。
- 新版健康检查失败，且数据库结构、迁移记录都未变化时，自动退回旧镜像，保留当前数据库，不丢弃刚录入的数据；本次发布仍返回失败。
- 数据库结构或迁移记录已变化时，停止应用并报错，不自动启动可能不兼容的旧版，也不自动恢复数据库。保留当前库和备份，核对迁移及新增数据后决定恢复步骤。
- SHA-256 用于发现传输损坏，不是签名；只运行自己生成的发布包。
- 文件锁阻止脚本并发发布。发布期间不要另外重启 Compose、迁移数据库或修改配置。

成功记录为 `deployment-state.json`；版本覆盖配置为 `.compose.release.yml`。以后手动使用 Compose，应在原 `-f docker-compose.yml`、可能存在的 `-f compose.staging.yml` 后面追加 `-f .compose.release.yml`，否则可能启动旧标签。日常继续双击发布脚本即可。

## 五、验证边界

独立测试使用临时 SQLite 和模拟 Docker，覆盖损坏包、错误标签/架构、WAL 备份、业务写入与迁移区分、错误挂载拒绝、更新成功、加载失败不中断旧版、备份失败恢复、失败退回镜像且保留新数据、迁移变化时停止。

```bash
python scripts/deploy/test_deployment.py
```

真实 Docker 构建、SSH/SCP、网页文件夹上传、已有 Caddy 及首次完整发布仍须对应环境验收；不能把模拟通过当成正式更新成功。
