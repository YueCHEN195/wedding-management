# 本地开发与验收

更新日期：2026-10-26。[文档入口](../README.md) · [测试用例](../测试/一期测试用例.md)

## 首次启动

使用Node >=24、pnpm；安装应用及独立代码检查工具：

```sh
pnpm install
pnpm lint:setup
cp .env.example .env
pnpm db:migrate
pnpm db:seed
pnpm dev
```

已有 `.env` 不覆盖。Windows复制命令为 `copy .env.example .env`。默认前端5173，后端3000；前端代理目前固定指向3000，更改后端PORT时需同时核对Vite配置。

`db:seed`创建缺失的两个账号，并在宾客表为空时插入示例宾客；已有账号跳过，不按新环境变量改密码。开发默认账号见 `.env.example`。服务启动自动执行已有迁移，不会自动运行seed；只有修改模型并准备新增迁移时才需要 `db:generate`。

环境配置修改后重启开发服务。`PUBLIC_BASE_URL`控制专属链接、二维码和海报目的地，手机不能访问电脑的localhost；要使用设备可达的地址。真实域名物料需重新生成并实际验扫。

## 手机 / 微信一键预览

```sh
pnpm preview:local
```

macOS / Linux 下通过 Bash 加载 nvm 并执行 `nvm use 24`，然后复用开发启动器。需先安装依赖、nvm及Node 24；缺少Node版本时按提示运行 `nvm install 24`。若当前终端的包管理器不能启动，可直接用 `bash scripts/preview-local.sh`，同样自动切换Node。

命令自动识别本机局域网IPv4，优先选择常见物理网卡；前后端分别从5173、3000寻找空闲端口，不会复用或终止旧服务。前端监听局域网，API代理自动指向本次后端；健康检查通过后在终端输出请柬和签到二维码、后台地址。前后端使用同一个手机可达的 `PUBLIC_BASE_URL`，专属链接与后台生成的二维码也指向本次预览。配置仅传给子进程，不改写 `.env`；Vite使用独立的 `local-preview` 缓存。

手机与电脑需连接同一Wi-Fi，并允许系统防火墙接受本地连接。多网卡时命令列出可用地址；如果默认网卡无法从手机访问，可指定本机另一个地址：

```sh
PREVIEW_HOST=192.168.1.10 pnpm preview:local
```

地址替换为终端列出的本机IPv4。按Ctrl+C同时停止前后端。此命令沿用当前开发数据库，只自动执行已有迁移，不清空数据、不运行seed。需要隔离验收时先设置 `DB_PATH` 指向独立库；更换网络后重启命令并重新扫码。Windows仍使用已有开发命令，未提供nvm-windows切换封装。

## 常用命令

| 命令                                             | 用途                                             |
| ------------------------------------------------ | ------------------------------------------------ |
| `pnpm preview:local` | 自动切换Node24并启动手机扫码预览 |
| `pnpm dev`                                       | 并行启动后端与Vite                               |
| `pnpm build`、`pnpm start`                       | 构建前端；生产模式托管构建及API                  |
| `pnpm db:migrate`、`pnpm db:seed`                | 迁移；开发账号和示例数据                         |
| `pnpm db:generate`                               | 模型修改后生成迁移，验收已有功能不需要           |
| `pnpm check`                                     | lint、前端零警告、规则测试、类型、业务测试、构建 |
| `pnpm test`                                      | 业务自动化回归                                   |
| `pnpm test:e2e:setup`、`pnpm test:e2e`           | 安装隔离浏览器工具；构建并执行真实页面验收       |
| `pnpm format <文件>`、`pnpm format:check <文件>` | 仅格式化/检查指定范围                            |

## 自动化验收

```sh
pnpm test:e2e:setup
pnpm --dir tooling/e2e exec playwright install chromium
pnpm check
pnpm test:e2e
```

已有Chrome也可执行 `E2E_BROWSER_CHANNEL=chrome pnpm test:e2e`。浏览器工具与应用依赖隔离。测试入口使用随机端口、新建临时数据库及专用账号；每个场景重置本次临时业务数据，结束清理。结果、截图和失败trace位于 `test-results/phase1/<时间>/`，被git忽略。

浏览器验收运行真实生产构建及API；故障用例拦截响应或模拟离线。不要把本地窄屏模拟描述为微信/真机通过。完整范围、结果和限制见[测试用例](../测试/一期测试用例.md)与[测试报告](../测试/一期测试报告.md)。

## 手动验收库

先停止占用默认端口的开发服务，再显式指定独立路径；下面库会保留此前同一路径的测试数据：

```sh
pnpm exec cross-env DB_PATH=./data/acceptance.db pnpm db:migrate
pnpm exec cross-env DB_PATH=./data/acceptance.db pnpm db:seed
pnpm exec cross-env DB_PATH=./data/acceptance.db pnpm dev
```

测试使用虚构姓名和金额。结束后停止服务，再正常 `pnpm dev` 使用原环境配置。不要为了验收清空现有业务库。

## 多开发服务与动态模块故障

Vite缓存按mode隔离。主开发服务仍用默认development；额外验证前端服务使用：

```sh
pnpm dev:web --mode verification --host 127.0.0.1 --port 5189 --strictPort
```

独立前端服务仍代理当前3000后端；验证写入时必须确保后端也是隔离验收库，或拦截写入。优先使用自动化验收入口，避免误接真实数据。

仪表盘模块失败时先检查动态模块及图表依赖请求、端口和mode；不要通过并行启动另一个development实例反复覆盖缓存。应用错误恢复页提供重新加载，但不能替代排查失败资源。
