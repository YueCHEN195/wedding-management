# 代码质量与分层规范

更新日期：2026-10-23。规范描述当前约束，实施过程和旧测试数量已移至[历史归档](../归档/README.md)。协作、业务及设计边界同时遵循根目录[AGENTS.md](../../AGENTS.md)。

## 工具与门槛

Node >=24。应用保持TS7；ESLint/Prettier在 `tooling/eslint/` 独立安装并锁定TS6，不通过降级应用TypeScript解决工具兼容问题。

```sh
pnpm install
pnpm lint:setup
pnpm check
```

- `pnpm lint`：全项目扫描，错误阻止通过，历史服务端/测试警告保持可见。
- `pnpm lint:web`：整个前端零错误、零警告；`lint:pilot`仅兼容别名。
- `pnpm lint:test`：验证视图请求边界、前后端边界及Hooks等检查实际生效。
- `pnpm typecheck`：应用TS7类型检查；不能由工具内TS6分析替代。
- `pnpm test`、`pnpm build`：业务回归、生产构建；`pnpm check`包含上述检查。
- 浏览器另运行 `pnpm test:e2e`，安装及隔离方式见[本地开发与验收](本地开发与验收.md)。
- `pnpm format <范围>`、`format:check <范围>`只处理本次修改文件。禁止无关全库格式化、无说明eslint-disable或统一降级业务风险来消除警告。

具体规则以 `tooling/eslint/config.mjs`、工具包和锁文件为准。文件350行、函数200行、复杂度20、嵌套4层为职责评审提醒；测试长度豁免不代表正确性豁免。不能压行、空转发或机械拆函数来规避提醒。

## 分层

| 层            | 职责与边界                                                           |
| ------------- | -------------------------------------------------------------------- |
| 页面组合      | 角色入口、区块顺序、Hook与视图连接；简单页面不强造层级               |
| 功能Hook      | 请求、mutation、缓存刷新、提交锁、流程状态、版本冲突及未保存保护     |
| 功能视图      | 接收数据与操作；原生Form布局、校验呈现及局部交互保留在视图           |
| 公共组件/Hook | 跨功能重复且模式稳定时抽取，不建立万能Controller、CRUD框架或新请求库 |
| shared/server | 共享输入边界和解析；服务端业务身份、权限、状态、统计及事务           |

新纯视图用 `*.view.tsx` 或明确加入ESLint视图范围；禁止通过改名绕过请求边界。视图不得运行时导入API客户端、React Query或server，可导入DTO/查询结果类型。前端不得导入server，server不得导入web，shared不得依赖页面。

功能专属实现留在 `admin/<功能>/`、`invite/` 或 `checkin/`。例如现场审核用 `useReviewWorkbench`组合流程，`useReviewQueries`查询，`useReviewSubmission`提交，`useReviewRealtime`订阅；详情、队列和核对视图通过props连接。不要在多处复制相同缓存刷新和提交状态。

## 不得因重构改变的规则

- 姓名不是身份；按ID关联，显式核对同名，保护旧请求与旧选择。
- 复用shared金额/人数解析器及server服务；不在前端重算有效汇总或猜测后台状态。
- 保留提交标识、版本前置条件、失败输入、未保存保护、审计事务和角色白名单。
- 历史未知实到人数保留null；预计、实到、儿童及礼金分别按已确认口径处理。
- 共用组件修改前检查全部调用点；样式随组件加载，Portal和页面专属token作用域明确，见[公共UI边界](../design/公共UI边界.md)。

## 验证与记录

每次修改按协作规则执行lint和前端零警告检查，完成类型、构建、相关回归及 `git diff --check`。接口变更覆盖权限、关联、未知值和失败回滚；布局/交互用真实React检查桌面、短窗口、窄屏、长文本、空/加载/失败及焦点。

测试不写真实签到/礼金数据。日期、测试总数、实际通过结果和限制只写入[测试报告](../测试/一期测试报告.md)，不在规范末尾持续追加互相冲突的“本轮通过”快照。
