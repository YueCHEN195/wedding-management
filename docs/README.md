## 维护约定

- 用户最新明确指示优先。发现文档与代码不一致时，记录差异并核对；不能用“代码已经这样写”反推为已确认需求。
- 业务规则只维护在产品目录，技术文档说明实现并链接规则；设计文档不另定权限、人数或记账规则。
- 测试用例说明如何验证，测试报告记录某一版本的结果。测试数量、截图和通过结论不散落到每份设计规范中重复维护。
- 一次性的试点、迭代、问题修复记录归档；归档内保留原日期和当时结论，不继续维护进度。
- 新阶段修改当前文档，并在相关测试报告中记录验收；不要再追加“第N轮”使规范同时包含互相冲突的现状。
