# 一期功能与业务范围

更新日期：2026-10-23。本文整合用户已确认的流程与一期实现；原草案见[历史归档](../归档/README.md)。一期开发完成不代表正式部署或真机验收已完成，实际验证见[测试报告](../测试/一期测试报告.md)。

## 产品与角色

应用服务一场婚礼，包括后台、专属/通用请柬和自助签到。婚礼信息、文案、照片路径由代码配置，不提供后台配置或上传界面。当前没有多婚礼管理、在线支付、桌位分配、祝福墙和宾客账号系统。

| 能力                             | 管理员                             | 工作人员                         | 宾客                                            |
| -------------------------------- | ---------------------------------- | -------------------------------- | ----------------------------------------------- |
| 宾客档案                         | 维护、归档、恢复、导入导出         | 现场只读查询及必要人数           | 不公开名单                                      |
| 完整回执及祝福留言               | 列表、查看、修改                   | 禁止；只读取现场核对所需人数     | 凭专属链接或本浏览器私有凭证填写/修改自己的回执 |
| 现场核对                         | 审核、手工补录、驳回               | 审核、手工补录、驳回             | 自助提交姓名进入待审                            |
| 人数更正、撤销签到               | 允许，需原因并留痕                 | 禁止                             | 禁止                                            |
| 礼金                             | 登记、更正、作废、恢复、单笔及汇总 | 现场确认时登记；单笔只读，无汇总 | 不填写礼金                                      |
| 仪表盘、完整统计、导出、展示物料 | 允许                               | 禁止；可使用现场签到入口         | 公开页面和公共签到二维码                        |

权限以服务端白名单和角色检查为准，隐藏菜单不能代替权限控制。

## 婚前：档案、邀请与回执

1. 管理员录入宾客；姓名可重复，记录以编号识别。分组支持输入新名称或选择已有分组，手机号可留空，填写时校验11位大陆手机号格式。
2. 可导入xlsx；有效行保存，失败行按行号说明原因。当前不承诺CSV、批量修改分组或完整数据库一键备份等早期设想。
3. 专属链接和二维码绑定具体档案；通用请柬用于转发。照片和物料属于私人婚礼素材，部署后静态资源可被访问。
4. 专属回执关联原档案；通用回执使用私有修改凭证，同名不能据此找回或覆盖他人回执。
5. 回执记录出席/待定/缺席、预计总人数、其中儿童及留言。儿童包含在总人数内；非出席状态不计预计到场人数。
6. 管理员查看完整回执与汇总；工作人员只见现场所需人数信息。

## 当天：自助提交、代登记与现场确认

1. 宾客打开 `/checkin`，只提交姓名，进入待审核队列。工作人员也可“扫码 / 代登记”只提交姓名；成功开始下一位，失败保留原输入和提交标识。
2. 现场审核采用实时通知刷新，保留手动刷新；断线有备用刷新与重连补齐。宾客名单默认“已签到”。
3. 工作人员核对具体身份及实到总人数、其中儿童。已有有效出席回执可带入人数作为表单初值，仍须现场确认；刷新不能覆盖手填人数。
4. 同名按编号核对，可明确新增另一位同名宾客。候选均已签到且尚未明确选择时，默认新增；不覆盖已作出的选择。
5. 没有同名候选的临时来宾省略额外身份选择，不要求填写分组，新档案默认“临时到场”。
6. 礼金自愿。可直接“仅签到，不登记礼金”；选择登记时必须填写实际金额。仅签到不生成零元礼金记录，也不表示欠款。
7. 确认成功后才计入当前到场。也可直接手工补录并确认；同一操作重试不能重复签到或记礼金，新的一位同名宾客使用独立操作。

## 管理、纠错与记录

- 有有效确认签到即“已出席”，临时到场不能仍只显示未填回执；宾客管理对此类宾客仅保留归档和操作记录。
- 现场已签到详情可在当前页面更正人数和礼金，不跳转重新查找。更正原因支持快捷Tag和手工输入，必填；礼金表单校验失败滚动到错误项。
- 撤销签到不改变原邀请/回执，也不作废礼金；恢复沿用原记录，不再次记账。
- 独立礼金可不关联签到；同名候选需明确选编号或明确单独记礼金。一位宾客允许多笔正常礼金。
- 归档、驳回、撤销、作废、恢复均说明影响、填写原因并保留历史。详细矩阵与统计口径只维护在[数据操作与保留规则](数据操作与保留规则.md)。
- 并发编辑拒绝静默覆盖；失败保留输入，核对最新记录后再保存。保存、详情、刷新尽量保留原搜索、筛选和分页。

## 统计、导出与交互口径

预计出席来自有效出席回执；实到来自已确认签到，儿童包含在总数内。签到组数与人数独立，历史未知人数显示待补记，不能推算为0。有效礼金排除已作废记录。

管理员可导出宾客、回执、签到、礼金xlsx；签到及礼金导出保留撤销/作废等历史标记。业务导出不等同于可恢复的完整数据库备份。

后台采用“深侧栏 · 珊瑚”，宾客端采用“玄朱 · 浮光”。表格提供手动刷新，编号在姓名前辅助辨认；区分加载、真实空数据、失败及缓存旧数据。普通页面使用Content滚动，现场审核桌面为队列/名单双列工作台，核对在右侧抽屉。
