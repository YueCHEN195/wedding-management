# 数据操作与保留规则

更新日期：2026-10-26。[文档索引](../README.md) · [一期测试报告](../测试/一期测试报告.md)

当前系统不提供业务记录永久删除入口，空档案也统一归档。身份按ID关联，历史记录与关联保留；姓名相同不表示同一个人。

## 操作、权限与恢复

现场纠错按[现场纠错与权限](现场纠错与权限.md)执行：工作人员可处理签到及其关联礼金的更正、补记、撤销、作废、恢复和关联纠错，独立礼金仍限管理员。

| 对象       | 操作     | 权限             | 结果                                                               | 恢复                                     |
| ---------- | -------- | ---------------- | ------------------------------------------------------------------ | ---------------------------------------- |
| 宾客       | 归档     | 管理员           | 隐藏当前名单，专属请柬停用；保留原编号、回执、签到、礼金和所有关联 | 管理员填写原因恢复                       |
| 待审核签到 | 驳回     | 管理员、工作人员 | 原提交标记已驳回，不删除提交映射、不影响礼金                       | 可恢复为待审；已有其他有效签到时禁止恢复 |
| 已确认签到 | 撤销确认 | 管理员、工作人员 | 原签到标记已撤销，保留首次确认时间和关联礼金                       | 核对后恢复原确认；不会重新记礼金         |
| 礼金       | 作废     | 管理员；工作人员仅限签到关联礼金 | 原金额与关联保留，退出有效统计，不能直接编辑已作废记录             | 按原操作权限填写原因恢复原账目                 |

恢复签到前，如关联宾客已归档，须先恢复宾客；如该宾客已有其他待审或已确认签到，须先核对现有记录。礼金恢复与宾客是否在当前邀请名单无关。

## 每次操作必须满足

1. 先读取当前对象、编号、关联数量及金额，并显示本次对统计和关联的影响。
2. 填写1–200字操作原因；原因不能留空。
3. 后端重新检查角色、当前状态和确认时的数据快照。对象、关联数据或操作历史有变化，旧确认不得生效；重新展示最新影响后再确认。
4. 状态变更和操作记录在同一事务中提交。审计写入失败时，状态也必须回滚。
5. 保留操作者账号、角色、时间、原因及记录前后值。应用内没有修改、删除操作历史的入口。
6. 同一状态操作不能重复生效，恢复后使用原编号，不新增替代记录。

旧的三个DELETE接口返回409，不能绕过新流程。当前未提供永久清除、合并宾客、批量作废等入口。

## 统计与导出

| 操作           | 当前名单／预计出席                           | 当前到场                           | 有效礼金                 |
| -------------- | -------------------------------------------- | ---------------------------------- | ------------------------ |
| 归档宾客       | 排除该宾客及关联回执；未关联通用回执保持独立 | 已确认历史签到继续保留在到场统计中 | 不变                     |
| 恢复宾客       | 恢复名单及原回执预计人数                     | 不变                               | 不变                     |
| 驳回待审       | 不改回执                                     | 不计到场；恢复后仍需审核           | 不变                     |
| 撤销已确认签到 | 不改回执                                     | 减少对应确认记录                   | 不变                     |
| 恢复已确认签到 | 不改回执                                     | 恢复对应确认记录                   | 不新增礼金               |
| 作废礼金       | 不变                                         | 不变                               | 减少该笔金额与有效笔数   |
| 恢复礼金       | 不变                                         | 不变                               | 恢复该笔原金额与有效笔数 |

当前到场分别展示已确认签到组数、实到总人数和其中儿童数；儿童包含在总人数内，不重复相加。预计人数独立取有效出席回执。历史实到为NULL时明确待补记并单列未知组数，不能由预计人数推算为0或自动补齐。

宾客默认列表和名单导出只包含当前宾客，归档名单可单独筛选。回执列表保留历史并标记已归档宾客，汇总排除其预计出席。签到导出保留已驳回、已撤销状态；礼金导出保留所有原记录，分别列出原登记金额、有效金额和作废状态，不能将作废原金额误计为有效收入。

## 更正、幂等与历史范围

礼金自愿，未登记不表示欠款；仅签到不创建零元礼金。礼金新增、更正、作废和恢复保留审计；更正必填原因并核对版本，旧版本不能覆盖新账目。人数补记/更正需核对原值并留痕。原因可快捷选择，也可手工填写。

有有效确认签到即已出席；宾客管理仅提供归档与操作记录，撤销后恢复原邀请/回执展示，不伪造回执。人数和礼金更正可在现场审核当前页面完成。

同一操作的提交标识保留用于失败重试，不能重复写入；下一位同名宾客是新的独立操作。恢复使用原ID，不能通过恢复再次创建礼金。

迁移保留已有数据，不恢复此前已经物理删除的内容，不自动合并或清理历史重复档案。签到确认人等缺少历史字段时显示未记录，不从礼金操作者反推。普通宾客/回执编辑不承诺完整变更账本；收款核对、合并宾客等旧建议不列为已实现。
